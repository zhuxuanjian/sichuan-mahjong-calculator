# 四川麻将三工具扩展设计

## 文档关系与目标

本文是现有四川麻将听牌工具的整合扩展规格，覆盖此前的副露与计番设计，并新增对局算子和出牌听牌分析。实现完成后，网站包含三个通过顶部导航切换的工具：

1. 胡牌计算：默认首页，计算当前牌况可胡哪些牌及其番数。
2. 对局算子：按实际顺序录入杠牌与胡牌事件，计算四位玩家的最终收支。
3. 出牌分析：录入摸牌后的牌况，选择一张牌打出，查看听牌、余牌和番数。

网站继续作为纯静态前端运行，无需服务器，不上传牌局数据，并部署到现有 GitHub Pages。

## 统一规则基准

本工具使用双方已经确认的传统成都麻将项目规则：

- 只使用万、筒、条共 27 种牌，不使用字牌。
- 四川麻将不允许吃，副露只支持碰、明杠和暗杠。
- 4 番封顶。
- 胡牌底数为 1，胡牌支付额为 `1 × 2^最终番数`。
- 番数只影响胡牌底数，不放大杠牌收支。
- 自摸加 1 番。
- 不计算断幺九和全带幺。
- 不实现流局查花猪、查大叫或退税。
- 杠上炮不执行呼叫转移，只按杠上炮加 1 番；此前杠钱保持原结算。

四川麻将存在地区和牌桌差异，本工具以本文明确列出的约定为准。

## 应用结构与导航

应用采用单页三工具结构，不引入框架或后端。`index.html` 中保留三个独立工具容器，由路由状态决定显示内容：

- `#hu`：胡牌计算，作为无 hash 或未知 hash 时的默认页面。
- `#settlement`：对局算子。
- `#discard`：出牌分析。

顶部提供三段式交互导航。切换工具时不重新加载页面；浏览器前进、后退和直接访问 hash 均能恢复正确工具。三种工具共用牌定义、胡牌拆解、番数计算、副露校验及定缺规则，但各自维护独立的界面状态。

本版本不提供跨刷新持久化；刷新页面后从空状态开始。

## 共享牌况模型

### 牌与副露

一张牌使用稳定的花色与点数组合标识。副露结构包含类型和牌：

- 碰：三张相同牌。
- 明杠：四张相同牌；胡牌计算和出牌分析不区分直杠与补杠，因为二者对牌型相同。
- 暗杠：四张相同牌。

暗手牌与全部副露合计时，同一种牌不得超过四张。最多录入四组副露。非法添加操作直接阻止并说明原因。

### 手牌目标数

胡牌计算输入的是摸牌前的手牌：

`目标暗手牌数 = 13 - 3 × 副露组数`

出牌分析输入的是摸牌后的手牌：

`目标暗手牌数 = 14 - 3 × 副露组数`

杠的第四张是额外物理牌，不额外减少目标暗手牌数。

### 定缺

定缺可以选择万、筒或条。选定后立即检查暗手牌和副露：

- 定缺牌以红色边框、警示图标和文字提醒标记。
- 胡牌计算中，只要仍存在定缺牌，就不输出胡牌结果。
- 出牌分析中，只要暗手牌仍有定缺牌，就只允许选择定缺花色作为弃牌，其他牌置灰且不可选择。
- 编辑操作不被锁死，用户仍可继续增删牌或更改定缺。

## 胡牌拆解与计番

### 合法胡牌

引擎支持普通胡和七对：

- 普通胡：结合已有副露后，完整牌况为四组面子加一对将。
- 七对：仅在没有副露时成立；四张相同牌可作为两对，同时形成一根。
- 龙七对不作为独立固定番名，而由“七对 + 根”自然表达。

普通胡需要保留所有可行拆解，分别评价后选择原始番数最高的解释。七对与普通胡是互斥解释，不把两种解释中的番型合并。原始番相同时选择说明更具体且稳定排序靠前的解释。

### 番型

- 素胡：0 番；合法胡牌没有其他结构番型时显示。
- 大对子：+1 番；普通胡的四组面子全部为刻子或杠。
- 金钩钓：+1 番；已有四组副露，暗手牌以单张等将胡牌。
- 根：每根 +1 番；完整牌况中每一种四张相同牌计一根，包括明杠、暗杠和未开杠的四归一。
- 七对：+2 番。
- 清一色：+2 番；暗手牌、胡入牌和全部副露只含同一花色。
- 自摸：+1 番。
- 杠上花、杠上炮、抢杠胡、海底捞月：各 +1 番。

杠上花、海底捞月只与自摸组合；杠上炮、抢杠胡只与点炮组合。所有适用项目相加后得到原始番数，再封顶为 4 番。结果同时保留原始番数、最终番数、是否封顶和番型明细。

## 工具一：胡牌计算

### 输入

用户录入暗手牌、副露、定缺、胡牌方式和特殊情形。胡牌方式为点炮或自摸；特殊情形根据胡牌方式只展示合法选项，切换方式后不兼容的情形自动重置为普通。

### 计算流程

输入达到目标暗手牌数、全局牌数合法且不存在定缺牌时：

1. 枚举全局已知数量少于四张且不属于定缺花色的候选胡牌。
2. 临时加入候选牌并取得所有合法胡牌解释。
3. 对每种解释计算结构番、花色番和情境番。
4. 选择原始番数最高的解释并应用 4 番封顶。
5. 按牌面顺序返回所有候选。

### 输出

每张可胡牌显示牌面、最终番数、原始番数和番型明细。超过封顶时显示例如“4 番（已封顶，原始 5 番）”；素胡显示“0 番 · 素胡”。本页面不显示理论剩余张数，也不计算玩家收支。

## 工具二：对局算子

### 对局模型

固定四位玩家，可修改显示名称。算子维护按时间排列的事件列表。每次新增、删除、撤销或调整顺序后，都从第一条事件重新推演玩家状态、转账明细和余额，不在旧结果上做增量修补。

每位玩家具有：标识、名称、是否已胡、累计收入、累计支出和净收支。已胡玩家保留此前收支，但从胡牌事件结束后退出所有后续结算，不能再开杠、放杠、点炮、胡牌，也不再支付后续自摸或杠牌费用。

### 杠牌事件

- 暗杠：开杠者以外的每位尚未胡牌玩家各支付 2 给开杠者。
- 补杠：开杠者以外的每位尚未胡牌玩家各支付 1 给开杠者。
- 直杠：选择开杠者和放杠者；放杠者单独支付 2 给开杠者。

杠牌金额固定，不乘番数。事件只允许选择在该事件开始时仍未胡的玩家。

### 胡牌事件

- 点炮胡：选择一名放炮者及一名或多名胡牌者。每位胡牌者分别手动选择最终 0 至 4 番，放炮者分别向其支付 `2^最终番数`。所有胡牌者在整条一炮多响事件结算完成后同时退出。
- 自摸胡：选择一名胡牌者并手动选择最终 0 至 4 番。事件开始时每位其他未胡玩家都向胡牌者支付 `2^最终番数`，随后胡牌者退出。

手动选择的是最终结算番数，已包含自摸、杠上花、杠上炮等所有加番，算子不再自动修正。杠上炮不会转移之前的杠钱。

### 流水与收支

每条事件显示事件类型、参与者、番数（若适用）、逐笔付款和事件后的余额。页面持续显示每人的总收入、总支出、净收支和是否已胡，并校验四人的净收支合计恒为 0。

支持：

- 添加事件。
- 删除任意事件。
- 上移或下移事件以调整真实发生顺序。
- 撤销最后一次事件操作。
- 清空整局并二次确认。

若调整顺序会使某事件使用已经胡牌的玩家，则拒绝该次移动、保持原顺序并解释原因。删除较早事件后从头重算，后续事件只要仍合法就保留；若变为非法，则明确标记并停止在该事件处结算，要求用户修正或删除。

## 工具三：出牌分析

### 输入与选牌

用户录入摸牌后的暗手牌、副露和定缺。输入满足目标数量和全局牌数约束后，点击一张暗手牌作为拟打出的牌。同种牌的任意实体点击都表示打出一张该牌。

存在定缺牌时，仅定缺花色可点击为弃牌。切换拟弃牌后立即重新分析，不改变原始输入，方便比较不同打法。

### 听牌、余牌与番数

程序从暗手牌中临时移除拟弃牌，然后复用胡牌枚举和计番引擎。每种可胡牌显示：

- 胡入牌牌面与名称。
- 理论剩余张数。
- 点炮最终番数及番型明细。
- 自摸最终番数及番型明细。

点炮番数按普通点炮情境计算；自摸番数在同一牌型基础上加入自摸 +1，二者均应用 4 番封顶。尚未发生的杠上花、抢杠胡、杠上炮和海底捞月不预先计入。

理论剩余数量为：

`4 - 当前已知的该牌数量`

当前已知数量包括录入的全部摸牌后暗手牌、拟打出的那一张以及自己的全部副露。它不推测对手手牌，也不要求录入牌河。拟弃牌仍是已知且不可摸回的牌，因此必须计入。若结构上形成听牌但四张均已知，结果仍保留并标记“0 张／绝张”。未形成听牌时显示“打出后未听牌”。

## 状态与错误优先级

牌况工具的提示优先级为：全局同牌超限或副露非法、手牌数量不符、存在定缺牌、未听牌、有效结果。警示应就近显示，不能仅依赖颜色表达。

算子中的参与者下拉框只列出当前事件位置仍有效的玩家。提交事件前验证参与者互异、番数范围正确、一炮多响至少有一位胡牌者。无法计算的非法流水不得生成部分但看似完整的最终收支。

## 模块边界

- `mahjong.js`：牌标识、计数校验、普通胡所有拆解、七对判断和候选胡牌枚举。
- `scoring.js`：纯计番函数，接收完整牌况、胡牌解释、副露与情境，返回明细和封顶结果。
- `settlement.js`：纯事件推演器，接收四位玩家和有序事件，返回逐笔转账、事件后状态、最终收支及校验错误。
- `app.js`：hash 路由、三个工具的状态协调、DOM 事件和渲染。
- `index.html`：导航及三个工具容器。
- `styles.css`：共用牌面、副露、警示、结果、流水和响应式样式。

算法模块不访问 DOM。胡牌、计番和算子推演均可在 Node 测试中直接调用。

## 测试与验收

### 自动化测试

- 普通胡、七对、一至四组副露、多面听和多种拆法取最高番。
- 素胡、大对子、金钩钓、单根、多根、七对、清一色及其合法组合。
- 自摸和四种特殊情形、互斥情形、原始 4 番和超过 4 番封顶。
- 不把断幺九或全带幺计入番数。
- 定缺阻断、强制弃定缺、全局四张上限和副露后的目标牌数。
- 暗杠、补杠、直杠、点炮、自摸和一炮多响的逐笔收支。
- 胡牌玩家退出后不参与后续任何结算。
- 删除、撤销、顺序调整、非法顺序及重新推演。
- 所有合法算子案例均满足四人净收支总和为 0。
- 每个可选弃牌的听牌集合、点炮番、自摸番、理论余牌和绝张标记。

### 浏览器验收

在桌面和 375px 手机宽度下真实点击验证：

- 默认进入胡牌计算，三个 hash 路由及前进后退正常。
- 副露增删、定缺警示、目标手牌数、计番明细、撤销和清空正常。
- 算子事件新增、多人胡、排序、删除、退出状态和收支卡同步更新。
- 出牌选择受定缺约束，切换弃牌会立即刷新听牌、余牌和两种番数。
- 页面无横向滚动，关键按钮可触控，错误提示可读。
- GitHub Pages 线上版本加载和交互正常。

## 完成标准

- 默认首页仍是胡牌计算，用户可在三个工具之间无刷新切换。
- 三个工具共享一致的牌数、副露、定缺、胡牌和番数规则。
- 对局算子能按手动事件顺序准确结算，并给出可核对的流水和四人最终收支。
- 出牌分析能对选择的弃牌给出听牌、理论余牌、点炮番与自摸番。
- 全部自动化测试与桌面、手机浏览器验收通过。
- 更新后的静态文件部署到现有 GitHub Pages，公开网址保持不变。
