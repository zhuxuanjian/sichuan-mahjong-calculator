# 四川麻将两工具极简版设计

## 目标

将现有三工具网站精简为两个只处理暗手牌的工具：

1. 胡哪些牌：输入未摸牌状态的暗手牌，显示可以胡哪些牌。
2. 出牌建议：输入摸牌后的暗手牌，选择一张弃牌，显示弃牌后可以胡哪些牌及理论剩余张数。

删除副露、杠牌、计番、胡牌情境和牌局结算，使手机录牌更直接。现有 GitHub Pages 网址保持不变。

## 页面结构与导航

应用继续采用纯静态单页结构，只保留两个 hash 路由：

- `#hu`：默认页面“胡哪些牌”。无 hash、未知 hash 及旧的 `#settlement` 均回退到此页面。
- `#discard`：出牌建议。

顶部导航只有“胡哪些牌”和“出牌建议”两个按钮。页面切换不刷新浏览器，各页面状态互相独立。

牌局结算页面、四人收支卡、事件表单、事件流水和结算入口全部删除。

## 删除范围

从界面、运行代码、测试、文档和离线包中删除：

- 碰、明杠、暗杠及所有副露录入。
- 副露对目标手牌数、全局牌数和胡牌结构的影响。
- 胡牌方式和特殊胡牌情境。
- 素胡、大对子、金钩钓、根、七对番、清一色及所有番数计算和明细展示。
- 点炮番、自摸番和 4 番封顶展示。
- 牌局结算引擎、页面和测试。
- `scoring.js`、`settlement.js`、`settlement-page.js` 及只服务于这些功能的样式和脚本引用。

七对仍作为胡牌结构参与合法性判断，但不显示“七对”等牌型文字，也不计番。

## 共同输入规则

- 使用万、筒、条 27 种牌。
- 同一种牌最多四张。
- 一手最多输入 14 张。
- 保留万、筒、条定缺选择。
- 暗手牌立即排序，点击当前手牌可删除，支持撤销和清空。
- 输入与计算全部在浏览器本机完成，不保存或上传。

## 不相公判定

不再强制胡牌页正好 13 张、出牌页正好 14 张。按暗手牌张数的模 3 状态判断：

### 胡哪些牌

允许 `1、4、7、10、13` 张，即当前张数满足 `count % 3 === 1` 且不超过 13。加入一张候选后，牌组应能组成若干面子加一对将。

### 出牌建议

允许 `2、5、8、11、14` 张，即当前张数满足 `count % 3 === 2` 且不超过 14。选择一张弃牌后，剩余张数进入胡哪些牌的合法状态。

其他非零张数显示“当前手牌相公”，并明确列出当前页面支持的张数，不调用胡牌分析。零张时显示继续添加手牌的提示。

## 胡牌结构算法

普通胡不再假设完整牌一定包含四组面子。对加入候选后的暗手牌：

- 总张数必须满足 `total % 3 === 2`。
- 自动推导需要的面子数为 `(total - 2) / 3`。
- 枚举将牌后，剩余牌必须恰好拆成相应数量的顺子或刻子。
- 支持 2、5、8、11、14 张完成牌况。

七对仅在完成牌为 14 张且七个对子成立时参与合法性判断。同一张候选无论存在多少种胡牌解释，都只在结果中显示一次。

候选牌不能属于定缺花色，且加入后同牌数量不能超过四张。

## 工具一：胡哪些牌

页面顺序：

1. 选择定缺。
2. 选牌区。
3. 紧接选牌区下方的当前手牌。
4. 可胡牌结果。

计算条件：

- 当前手牌张数属于 `1、4、7、10、13`。
- 已选择定缺。
- 当前手牌中不存在定缺花色。
- 牌数合法且同牌不超过四张。

结果只显示每一种可胡牌的牌面和名称。页面不得出现牌型、番数、胡牌方式、特殊情境或理论剩余张数。无可胡牌时显示“当前手牌未听牌”。

## 工具二：出牌建议

页面顺序与胡牌页一致：定缺、选牌区、紧接其下的当前手牌和结果。

计算条件：

- 当前手牌张数属于 `2、5、8、11、14`。
- 已选择定缺。
- 选择一张当前手牌作为拟弃牌，选择不会从显示手牌中移除该牌。

若手牌仍有定缺牌，只允许选择定缺花色作为弃牌，其他牌不可点击。弃牌后仍有定缺牌时，提示继续打定缺，不显示听牌结果。

合法分析结果按弃牌选择显示：

- “打出 ×× 后胡”标题。
- 每种可胡牌的牌面和名称。
- 理论剩余张数。
- 四张均已知时保留结构等待并显示“0 张／绝张”。

页面不得显示点炮番、自摸番、牌型或封顶信息。

理论剩余张数为 `4 - 输入手牌中该牌的数量`。拟弃牌仍属于已知且不可立即摸回的牌，因此保留在已知数量内。不推测对手手牌，也不录入牌河。

## 手机布局

在手机宽度下：

- 每个花色的 9 个选牌按钮按容器宽度等比缩小，始终保持一行。
- 当前手牌紧接选牌区下方，最多 14 张按容器宽度等比缩小，始终保持一行。
- 两处不得换行或产生横向滚动。
- 当前手牌仍能逐张点击删除，并以清晰的选中样式标记出牌建议中的拟弃牌。
- 桌面端继续使用较大的牌面尺寸。

当前手牌必须与选牌区处于同一操作段落，录牌后无需越过其他功能区才能看到新增牌。

## 状态与错误优先级

两页共同采用：

1. 非法牌数或同牌超过四张。
2. 当前张数不属于本页允许的张数。
3. 未选择定缺。
4. 仍有定缺牌。
5. 未听牌或有效结果。

出牌建议页在张数和定缺合法后，再提示选择弃牌。

## 模块调整

- `mahjong.js`：保留牌定义、计数校验、可变面子数普通胡、14 张七对、候选胡牌及弃牌分析。
- `hu-page.js`：只管理暗手牌、定缺、撤销/清空和可胡牌渲染。
- `discard-page.js`：只管理暗手牌、定缺、弃牌选择、余牌和结果渲染。
- `ui-common.js`：保留牌面和移动端共用渲染辅助，删除副露辅助。
- `app.js`：只管理 `hu` 与 `discard` 两个路由。
- `index.html`、`styles.css`：删除结算、副露、计番和胡牌情境结构与样式，重排手机牌面。

## 测试与验收

自动化测试覆盖：

- 胡牌页所有合法张数 `1、4、7、10、13`。
- 出牌页所有合法张数 `2、5、8、11、14`。
- 两页的相公张数提示。
- 2、5、8、11、14 张完成牌况的普通胡拆解。
- 14 张七对合法性、多面听、第五张排除和结果去重。
- 定缺阻断与出牌页强制先弃定缺。
- 出牌后的理论余牌和绝张。
- 结果中不存在番数、牌型或胡牌情境字段。
- 旧 `settlement` 路由回退到 `hu`。

真实浏览器在桌面与 375px 手机宽度验收：

- 两页导航、前进/后退和状态保持。
- 添加牌后，当前手牌位于选牌区正下方并立即更新。
- 每花色 9 张牌保持一行。
- 最多 14 张当前手牌保持一行。
- 页面整体无横向滚动。
- 胡牌页只显示可胡牌。
- 出牌页只显示弃牌、可胡牌和理论余牌。
- 网页与 ZIP 解压版本均通过相同流程。

## 完成标准

- 网站仅保留“胡哪些牌”和“出牌建议”。
- 所有副露、杠牌、结算、情境、牌型和番数功能及代码从运行版本删除。
- 合法张数按模 3 自动计算，其他张数明确提示相公。
- 手机选牌和当前手牌均为单行等比缩放布局。
- 自动化测试和桌面/375px 浏览器验收通过。
- README、离线包和现有 GitHub Pages 更新成功。
